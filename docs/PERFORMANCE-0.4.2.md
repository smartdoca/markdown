# 0.4.2 · 千行协同编辑性能

## 定位与优化

在同一台机器、同一浏览器、同一隔离宿主 fixture 上比较：1,000 行、24,781 UTF-16 字符，包含 250 个标题、格式、链接、中文/emoji 和行内代码，两个页面同步 30 次插入，每次目标间隔 25ms。

同步 dispatch 的中位耗时约 2ms；原分栏每次输入都重新进行全文 Markdown 解析、精确位置映射、HTML 重解析和 React DOM 更新，输入间隔显著增加。仅编辑对照没有这种退化。本轮定位的是包内预览瓶颈，不是对 Doca 网络/宿主监听的性能结论。

| 同一测试场景 | 优化前 | 优化后源码构建 |
| --- | ---: | ---: |
| 仅编辑输入间隔 p50 | 28.7ms | 28.4ms |
| 分栏输入间隔 p50 | 178.8ms | 28.1ms |
| 分栏输入间隔 p95 | 275.1ms | 29.0ms |
| 分栏 30 次输入总用时 | 5827.0ms | 850.1ms |
| 本页预览 DOM 提交批次 | 30 | 1 |

这是包含固定 25ms 等待的测试输入间隔，不是原生键盘 input-to-paint 指标，也不是网络 RTT；单次局部样本，受机器/浏览器负载影响，不能作为所有用户的性能保证。

实现：

- 大文档预览延后到停止输入后 150ms 合并刷新；源码与 Yjs 更新不延迟。阈值为 10k UTF-16 单元或 500 行，小文档即时刷新。纯编辑不调度预览。
- `previewDebounceMs` 可覆盖等待时间；0 关闭，范围截断为 0–2000ms。
- memo 隔离 CodeMirror 的无关父组件更新；空选区不再做全文一致性比较/锚点构造。
- 无原始 HTML 的源文跳过 `rehypeRaw`，仍保留 sanitize；存在 `<` 时继续原有解析路径。
- 没有评论时不进行预览装饰的布局测量；源码选区不再触发预览选区的全文检查。

## 一致性与限制

预览滞后期间明确标记 busy，拒绝将旧 DOM 偏移应用到新模型。已有相对选区及评论在最新投影提交后恢复。源码、导出、find/replace、撤销、原始 CRDT bytes 不经过预览调度。

已测千行双页准确收敛、零远端回声、实例不变；延迟期间旧预览捕获返回 null；恢复相对选区/评论、只预览定位、undo、导出即时原文、配置变化不重建。打包安装后的复验、其他回归与实际 60 秒静置结果见根目录 `DELIVERY-0.4.2.md`。

持续不断输入时预览保留上一份完整快照，直到输入暂停；这不是逐键实时预览。尚未实现 Worker、增量 Markdown 语法树、预览虚拟化；停止输入后的单次全文渲染仍有成本。大量图表/海量评论/超大文件及宿主昂贵的 onChange 逻辑仍可能卡顿。没有修改宿主 ACK、outbox 或新增保存通道。

复跑：`yarn test:browser` 后打开 `/tests/browser/index.html`，点击“运行千行编辑性能对比”。源码和实际安装产物可分别通过默认入口和 `EXMD_TEST_PACKAGE_DIR` 比较。使用隔离文档，不操作用户文档。
